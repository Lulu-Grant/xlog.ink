# tool.gls.lat

Lightweight PHP toolbox site for `tool.gls.lat`.

Primary development rules live in `docs/DEVELOPMENT_GUIDE.md`.
Architecture history and future tool expansion notes live in `docs/EXPANSION_LOG.md`.

## Architecture

- `app/bootstrap.php`
  Central app bootstrap for language loading, tool registry access, SEO helpers, runtime storage, and download tokens.
- `app/tools.php`
  Tool registry. New tools should be registered here first.
- `inc/header.php` and `inc/footer.php`
  Shared layout, theme switcher, language switcher, canonical tags, and hreflang output.
- `index.php`
  Homepage that renders tool cards directly from the registry.
- `tools/`
  One PHP entry file per tool page.
- `lang/`
  Translation files keyed by shared labels and tool metadata. The current setup includes both Traditional Chinese (`zh`) and Simplified Chinese (`zh-cn`), so new tools should update both.
- `download.php`
  Controlled file download endpoint backed by private runtime storage in the system temp directory.
- `sitemap.php`
  Dynamic sitemap generated from the tool registry.

## Adding a New Tool

1. Add a new entry to `app/tools.php`.
2. Create a new page in `tools/` using an ASCII slug such as `my-new-tool.php`.
3. If replacing an older URL, keep the old file as a small compatibility wrapper.
4. Add the translated strings to every file in `lang/`.
5. The homepage and sitemap will pick up the new tool automatically from the registry.

## Runtime Notes

- Generated downloads are stored under `sys_get_temp_dir() . '/toolsgualaoshi'`.
- Download links are temporary and resolved through `download.php`.
- Old runtime files are cleaned up automatically based on the configured TTL.
- Production should keep legacy public runtime folders such as `tmp/` and `uploads/` blocked from direct web access.
- The production `.user.ini` open_basedir is:
  `/www/wwwroot/tool.gls.lat/:/tmp/:/usr/bin/:/opt/google/chrome/`

## Production Dependencies

The document conversion tool requires these binaries on the server:

- `pandoc`
- `pdftotext` from `poppler-utils`
- `google-chrome-stable`

DOCX to PDF uses Pandoc plus headless Google Chrome. PDF to DOCX uses `pdftotext` when available, then falls back to the internal parser.

## Production Hardening

- Nginx config sample lives at `deploy/nginx/tool.gls.lat.conf`.
- TLS should only allow TLS 1.2 and TLS 1.3.
- Direct access to internals should return 404:
  `/config.php`, `/router.php`, `/app/`, `/inc/`, `/lang/`, `/docs/`, `/scaffolds/`, `/test-results/`, `/tmp/`, and `/uploads/`.
- macOS AppleDouble files (`._*`) are ignored and should not be deployed.
- Runtime files generated by conversions should remain outside the public document root under `/tmp/toolsgualaoshi`.

## Deployment Check

After changing server config or conversion dependencies, run:

```bash
nginx -t
apt-get check
curl -I -H 'Host: tool.gls.lat' http://127.0.0.1/
curl -I -H 'Host: tool.gls.lat' http://127.0.0.1/config.php
```

Expected results:

- `/` returns `200`.
- `/word-pdf-converter` returns `200`.
- `/config.php` and internal folders return `404`.
- DOCX to PDF generates a valid PDF.
- PDF to DOCX generates a valid DOCX.

## Frontend Styles

- Utility classes are compiled into `assets/css/tailwind.min.css`.
- Rebuild the stylesheet with:
  `npx --yes tailwindcss@3.4.17 -c ./tailwind.config.js -i ./assets/css/tailwind.source.css -o ./assets/css/tailwind.min.css --minify`

## Scaffolds

- New tool starter files live in `scaffolds/`.
- Use them for page structure, registry entries, and translation keys before wiring the real logic.
