# xlog.ink V2 第七轮大型综合审计

> 审计日期：2026-07-26  
> 审计基线：`e9eb8ae` + 当前工作区未提交改动  
> 候选文件集 SHA-256：`caf2400a6d5c69e99f0bdc4dcb2907ac310d04de06b395adb9200bf81b1f3feb`  
> 范围：安全、会话与权限、支付与积分、生成链路、数据与运维、代码结构、复用性、冗余文件  
> **整改开发文档：** [`AUDIT-7-NEXT-DEV.md`](./AUDIT-7-NEXT-DEV.md)

## 一、结论

当前项目已具备完整产品主链路，前五轮修过的 SQL 参数化、额度原子扣减、生成锁、上传限制、AI 成人审核 fail-closed、内部目录 Nginx 屏蔽、访问统计限流等机制仍然有效。

本轮没有发现仓库内明文 API Key、直接 SQL 注入或公开目录任意文件上传，但发现：

- 5 项 P1：会话认领绕过归属校验、支付渠道硬删除、支付金额缺失时 fail-open、测试污染真实数据库、生成页允许不受控内联脚本。
- 9 项 P2：部署 CSP 范围、截图缓存与统计污染、上游错误泄漏、密钥落库、mock 静默降级、数据库迁移与依赖复现等。
- 多项结构与仓库卫生问题：三个超大单体文件、一份明确死代码、一个临时脚本、约 17 MB 重复 PNG 母版、历史文档缺少归档层。

上线状态应判定为：**主链路可用，但支付和账号认领模块尚不适合未经修复直接放量。**

## 二、P1：优先修复

### P1-1 登录后可认领不属于当前浏览器的匿名会话

证据：

- `api/auth/verify.php:42-44` 接受前端任意 `session_id` 并调用 `claim_pages_after_login()`。
- `api/auth/me.php:24-31` 对已登录用户重复开放同一路径。
- `includes/page_edit.php:124-145` 的 `bind_session_to_user()` 只检查 `sessions.user_id`，未调用 `session_access_allowed()`。
- 项目其他 session API 均通过 `includes/db.php:310-322` 校验 `client_id` 或 IP。

影响：

攻击者若获得一个尚未绑定用户的 session ID，可在自己的登录态中把会话绑定给自己，并认领该会话生成的匿名页面。session ID 随机性足够，无法直接枚举，但泄漏后的权限边界是失效的。

修复：

1. `claim_pages_after_login()` 接收 session 前必须查询完整 session 并执行 `session_access_allowed()`。
2. `bind_session_to_user()` 增加明确的浏览器归属证明参数，不能仅依赖“当前未绑定”。
3. 增加负向测试：已登录用户提交另一浏览器创建的未绑定 session，必须拒绝且 owner 不变。

### P1-2 支付渠道可硬删除，未完成订单会失去验签能力

证据：

- `partials/admin/channels.php:44-49` 对所有渠道提供“删除”。
- `includes/pay.php:295-299` 直接 `DELETE FROM pay_channels`。
- `includes/pay.php:356-372` 回调需要原渠道密钥验签。
- `includes/pay.php:581-594` 找不到原渠道后会错误回退到同支付类型或首个启用渠道。

影响：

管理员删除仍有 pending 订单的渠道后，延迟回调可能无法验签，已付款用户收不到积分；主动查询还可能使用另一渠道凭据查询旧订单。此问题直接影响到账与对账。

修复：

1. 去掉硬删除，改为 `enabled=0` 的软停用。
2. 若存在 pending/paid 历史订单，禁止删除渠道记录。
3. 查询与回调必须只使用订单快照的渠道，不允许静默换渠道。
4. 长期方案是在订单中保存不可变的 gateway/channel 版本引用。

### P1-3 支付回调和主动查询缺少金额时仍可入账

证据：

- `api/pay/notify.php:77-81` 将可能为空的 `money` 传给入账函数。
- `includes/pay.php:443-451` 约定空金额直接视为匹配。
- `includes/pay.php:780-785` 仅在金额非空时比较。
- `includes/pay.php:840-844` 主动查询缺少 `money` 时同样可完成订单。

影响：

只要网关返回“已支付”且签名有效，缺失金额字段也会为订单发放完整积分。网关协议变更、异常响应或错误渠道查询都可能触发错误入账。

修复：

1. notify 和 query 两条入账路径都必须存在合法金额。
2. 金额必须按分精确等于 `orders.amount_cents`。
3. 同时校验订单号、商户 PID、渠道 ID、支付方式和交易号。
4. 不满足时保持 pending，记录可检索的 reconciliation error。

### P1-4 测试脚本直接写当前配置的真实 SQLite

证据：

- `scripts/test-admin-tabs.php:99-179` 创建用户、订单和积分流水，结束时没有清理。
- `scripts/test-guest-user-flow.php:250` 明确写着 `leave rows`。
- README 把部分脚本作为普通测试命令提供，但没有隔离环境警告。
- 当前数据库已有 19 个测试用户、16 个关联订单、49 条关联积分流水。

影响：

测试会污染后台统计、订单列表、用户积分和审计结果；若在生产目录运行，污染直接进入生产数据库。

修复：

1. 所有集成测试沿用 `scripts/test-logic-review.php` 模式：临时目录、临时 config、独立 SQLite。
2. 测试入口检测 `data_dir`，拒绝对默认/生产路径运行。
3. 使用 `try/finally` 删除临时目录。
4. 单独编写一次性清理脚本，先 dry-run 列出这 19/16/49 条污染记录，人工确认后再删。

### P1-5 AI 生成 HTML 仍可执行任意内联 JavaScript

证据：

- `api/publish.php:372-385` 只拒绝外链 script、iframe、form 和非本站图片。
- `api/publish.php:435-441` 的 CSP 明确包含 `script-src 'unsafe-inline'`。
- `prompts/gen-system.txt:6` 允许模型输出内联 script。

当前可通过校验的内容包括：

- 任意内联 `<script>`。
- `onclick` 等事件属性。
- `javascript:` 链接。
- `meta refresh` 跳转。
- 无限循环、弹窗、全屏诱导和高 CPU 脚本。

影响：

生成内容来自用户提示词和外部模型，属于不可信输入。虽然主站 cookie 是 host-only、CSP 禁止 connect/form，恶意脚本仍可在可信的 `*.xlog.ink` 域名上做跳转、欺骗和资源滥用。

修复建议：

1. 默认移除所有脚本和 `on*` 属性，生成页以纯 HTML/CSS 为安全基线。
2. 需要倒计时、菜单等交互时，使用平台维护的受信任组件脚本，不让模型自由写 JS。
3. 用 DOM 解析器和标签/属性 allowlist 代替正则验证。
4. CSP 移除 `script-src 'unsafe-inline'`；确有脚本时使用固定 hash/nonce。

## 三、P2：尽快修复

### P2-1 Nginx 示例把生成页 CSP 写在“主域/通配符共用 server”

`docs/nginx-v2-snippet.conf:1-2` 要求放入共用 server，但 `:42-46` 无条件添加极严格 CSP。照文档部署会同时影响主站，阻断主站外部 CSS/JS/Turnstile。

应拆分 `xlog.ink` 与 `*.xlog.ink` server，或使用 host map 只给生成页发送该 CSP。

### P2-2 页面截图使用固定 URL，但静态资源配置为 30 天 immutable

- `includes/content_tools.php:416-417` 永远写 `/site-assets/{slug}/page-shot.png`。
- `docs/nginx-v2-snippet.conf:35-38` 对整个目录启用 `immutable`。

编辑页面后浏览器/CDN 可能继续显示旧截图。应改为内容 hash 文件名，或只对不可变上传资源设置 immutable。

### P2-3 自动截图会污染访问统计

发布流程先注入 `/api/visit.php` 像素，再用 Playwright 打开最终 HTML：

- `api/publish.php:397-418`
- `api/publish.php:236-260`
- `includes/content_tools.php:408-427`

每次发布/编辑截图都可能被记录为一次真实访问。截图请求应携带内部标记并让 visit API 忽略，或在注入统计像素前截图。

### P2-4 API 向用户返回上游和内部异常原文

- `api/chat.php:83-85`
- `api/upload.php:29-31`
- `api/pay/create.php:79-86`
- `includes/ai.php:471-499` 会组合供应商、模型和网关错误。

这会泄露模型名、网关状态、支付错误和内部实现。客户端只返回稳定本地化错误码；详细异常进入 `error_log`，并附 correlation ID。

### P2-5 支付密钥明文存入 webroot 下的 SQLite

`includes/pay.php:225-292` 将 MD5、商户私钥、平台公钥写入 `data/xlog.db`。Nginx deny 正常时数据库不可下载，但一次配置回归会同时暴露用户、会话和支付密钥。

建议数据库只保存渠道元数据和 secret reference，真实密钥放 `/etc/xlog/config.php`；至少要做应用层加密和密钥轮换。

### P2-6 AI 缺 key 时自动进入机械 mock

- `includes/ai.php:48-63` 缺 chat/gen key 时静默运行 mock。
- `includes/ai.php:670-707` 用关键词正则触发动作。
- `includes/ai.php:710-739` 可生成演示 HTML。

这与“动作只由真实 AI 判断”的产品边界不一致，也会让生产配置缺失时看似成功、实际发布假页面。mock 应只在显式 `app.env=local && ai.mock=true` 时启用；生产缺 key 必须 fail closed。

### P2-7 数据库没有版本化迁移，也没有实际外键

`includes/db.php` 每次连接执行建表和 `db_ensure_column()`；虽然设置了 `PRAGMA foreign_keys=ON`，表结构没有任何 `FOREIGN KEY`。

结果是：

- channel、user、session、page、image、order 可产生孤儿关系。
- 无 schema version，生产升级和回滚无法确认执行到哪一版。
- 删除渠道不会被数据库阻止。

建议引入 `schema_migrations` 和按版本执行的事务迁移；新增关键外键或至少显式引用检查。

### P2-8 截图依赖不可复现，代码含本机绝对路径

- 仓库没有 `package.json`/lockfile。
- `scripts/capture-page.js:14-23` 尝试多个全局路径，并包含 `/Users/apple/...`。
- `scripts/codex-dynamic-audit.js` 也依赖本机 Codex runtime。

应增加最小 `package.json` 和锁文件，把 Playwright 版本固定；生产浏览器路径由环境变量提供，不应写开发机路径。

### P2-9 普通 session/cid/locale cookie 的 HTTPS 判断不支持可信反代

`includes/bootstrap.php:204-242` 和 `includes/helpers.php:87-96` 只看 `HTTPS=on`；admin cookie 则额外看 `X-Forwarded-Proto`。

若 TLS 在可信反代终止且 PHP 收到 HTTP，登录和 client-id cookie 会缺少 Secure。应集中实现一个仅信任已配置代理的 `request_is_https()` 并供全部 cookie/base URL 使用。

## 四、P3：代码结构与仓库卫生

### P3-1 三个单体文件已超过合理维护边界

- `js/ai-app.js`：约 70 KB、81 个函数，混合状态、SSE、聊天卡片、上传、登录、支付、抽屉。
- `includes/pay.php`：约 34 KB、39 个函数，混合渠道仓储、签名、HTTP、订单、回调、对账。
- `includes/i18n.php`：约 67 KB，所有语言和业务域混在同一数组。

建议拆分：

- 前端：`state/session`、`sse`、`cards`、`auth`、`billing`、`uploads`。
- 支付：`ChannelRepository`、driver、gateway client、OrderService、reconcile。
- i18n：按 locale 或业务域拆文件，启动时加载当前 locale。

### P3-2 明确死代码

`includes/markdown.php` 共 142 行，仓库内没有任何调用方。确认旧入口不再依赖后应删除，并用一次全链路回归证明。

### P3-3 明确临时垃圾文件

`scripts/_tmp_admin_post.php`：

- 未被 Git 忽略。
- 包含本机绝对路径。
- 读取真实 admin token 并直接 include 后台。

应删除，并在 `.gitignore` 增加 `scripts/_tmp_*`。

### P3-4 宣传素材重复占用仓库

仓库非运行时代码约 21.4 MB，其中 9 张 AI 原始 PNG 约 17 MB，同时已有对应 WebP 和渲染稿。Git pack 已约 40.85 MB。

建议：

- 运行仓库只保留优化 WebP 和最终选中的宣传成品。
- 原始 PNG 母版移到 Git LFS、Release 附件或独立素材仓库。
- 不要直接删除尚未确认的设计母版。

### P3-5 文档缺少“当前/归档”边界

`docs/` 同时存在 V2 定稿、六轮历史审计、多个 `*-NEXT-DEV.md` 和当前验收文档。内容有价值，但读者无法快速判断哪份有效。

建议：

- `docs/current/`：V2 设计、部署、支付 runbook、最新审计。
- `docs/archive/audits/`：历史审计。
- `docs/archive/plans/`：已完成开发计划。
- 根目录保留 `docs/README.md` 作为文档索引。

### P3-6 部署脚本过度绑定单台服务器

`scripts/deploy-code.sh` 默认写死 IP、宝塔 PHP 路径、目标目录和 `www:www`。环境变量可覆盖，但默认行为不适合作为可复用工具。

建议提供 `deploy.example.env`，要求显式 target；`--check` 同时检查 Nginx deny、config 权限、Playwright、cron、PHP 扩展和目录属主。

## 五、环境与运行风险

### E1 Turnstile 当前有效配置为关闭

当前配置摘要显示 `turnstile.enabled=false`。这不是代码漏洞，但会把游客生成成本防线退化为 IP/cookie 日额度，代理池可放大成本。

生产应开启 Turnstile，并把“Turnstile 配置存在且 live verify 通过”设为部署阻断项。

### E2 支付渠道允许 HTTP API 地址

`includes/pay.php:236-238` 接受 `http://`。生产渠道必须强制 HTTPS；仅测试环境可显式允许 localhost HTTP。

### E3 支付 URL 未校验协议

网关返回的 `pay_info/payurl/qrcode` 直接传给前端，`js/ai-app.js:870-877` 使用 `window.open()`。应只接受可信 HTTPS 网关/支付 URL，拒绝 `javascript:`、`data:` 和非预期 host。
