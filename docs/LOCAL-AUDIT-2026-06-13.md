# xlog.ink V2 本地综合审计报告

审计日期：2026-06-13  
审计范围：本地代码合理性、接口链路、安全与成本控制、UI/UX、三语与新功能落地状态。  
部署状态：仅本地审计，不上线、不同步生产。

## 1. 结论摘要

当前 V2 的主体架构是合理的：PHP API、SQLite、原生 JS、提示词协议、图片处理、额度控制、邮件 token、编辑权限、三语 UI、AI 生成图片、自动成人内容判断、SEO/OG、页面截图导出等模块已经形成闭环。前几轮审计中指出的高危问题（webroot 内部目录暴露、先生成后扣额度、上传滥用、编辑图片丢失、同会话并发生成、邮箱误绑定、超长消息成本漏洞）在代码层面已经基本收口。

本地回归没有发现新的 P0 阻断问题。当前上线前最需要补齐的是生产级真实服务验证：本地 `config.php` 只配置了图片生成和 OpenAI Moderation，聊天模型、最终生成模型、SMTP、Turnstile 均未在本轮本地完整验证。

## 3. 代码结构审计

### 3.1 模块划分

整体分层清晰：

- `api/`：对外接口，单个文件职责较窄。
- `includes/db.php`：SQLite、schema、session、page、image 读写。
- `includes/ai.php`：聊天、生成、OpenAI Moderation、图片生成适配。
- `includes/quota.php`：生成、聊天、会话创建、上传、验证码、图片生成额度。
- `includes/imageproc.php`：上传图、AI 生成图、WebP 转换、图片成人分数。
- `includes/content_tools.php`：成人内容判断、slug 建议、SEO/OG、页面截图。
- `includes/i18n.php`：三语固定文案。
- `prompts/`：聊天阶段和生成阶段 prompt 独立维护。

这套结构适合当前规模，暂时不需要引入框架或构建链。

### 3.2 数据与权限

合理点：

- SQL 基本使用参数化。
- `session_access_allowed()` 已统一用于聊天、上传、发布、邮箱绑定等关键路径。
- owner edit 与 token edit 有不同入口。
- 页面重新生成保留原 slug 的能力已经具备。
- 图片移动时会同步更新 `images.path` 和会话消息中的旧 tmp URL，避免重复生成引用 404 tmp 资源。

需要注意：

- `recent.html` 是可生成产物但仍在 Git 追踪中。本地发布测试容易把它改脏。若后续频繁本地测试，建议明确它是“生成后可提交的静态索引”，还是改成部署时生成但不纳入源码提交。
- `quota_counters` 目前按日期增长，清理脚本尚未看到明显的历史 quota 清理策略。不是阻断，但长期运行后可以加保留期。

## 4. 安全与成本控制审计

### 4.1 已收口项

- 生成前扣额度，失败、拒绝、校验失败、写入失败会退款。
- 同一 session 正在生成时有服务端锁，降低双标签重复生成成本。
- 聊天单条消息限制到 4000 字符级别，降低 token 与 DB 膨胀风险。
- 图片 caption 限制到 200 字符级别。
- 上传图片限制文件大小、尺寸、每会话数量和每日上传额度。
- 图片会转 WebP 并剥离原始 EXIF。
- 生成 HTML 校验拒绝外链脚本、外链 CSS、iframe、form、非本站图片。
- 用户手写 `[[ACTION:...]]` 不作为前端动作来源。
- 邮箱自动绑定已收紧到“用户基本只输入邮箱”的语义，避免把页面联系方式误绑定成编辑邮箱。
- 真实凭据没有进入 Git 追踪文件；本轮 grep 未发现 tracked 文件中的 `sk-` 风格 key。

### 4.2 仍依赖生产配置的安全项

- 内部目录保护依赖生产 Nginx 规则：`/data/`、`/includes/`、`/prompts/`、`/scripts/` 必须 404/403。
- Turnstile 本地关闭，生产发布前必须打开并验证失败路径。
- 本地项目根存在 `config.php` 仅用于开发，生产应使用 `/etc/xlog/config.php`，避免把真实配置放进 webroot。

## 5. AI 功能审计

### 5.1 聊天动作协议

聊天 prompt 当前支持：

- `UPLOAD`
- `READY`
- `PUBLISH`
- `EMAIL`
- `DOMAIN`
- `IMAGE_GEN`

设计边界合理：模型只给“建议动作”，后端仍负责权限、额度、Turnstile、校验和发布裁决。

风险点：

- 动作标记要求出现在回复末尾。若模型把动作放在中间或后面继续输出文字，动作不会触发。这是可接受的稳定性取舍，但真实模型接入后应观察失败率。
- `DOMAIN` 目前会把域名偏好作为用户角色的系统事件写入会话，语义上可用，但从数据模型看略混杂。后续可考虑加 `session.preferences` 字段保存域名前缀偏好。

### 5.2 最终生成 prompt

合理点：

- 明确要求单文件 HTML、内联 CSS、禁止外链 JS/CSS/font/iframe/form。
- 要求 SEO 基础字段和单一 H1。
- 图片 URL 以图片清单 JSON 为最高优先级，修复了旧 tmp URL 冲突问题。
- 页面语言优先由用户需求和对话语言决定，不被 UI 语言强制覆盖。

限制：

- HTML 校验仍是正则策略，已经足够防普通外链和危险结构，但对极端对抗 HTML，DOM 级解析会更稳。

### 5.3 图片生成与成人内容判断

合理点：

- AI 生成图片只在用户明确要求时触发，不主动消耗。
- 图片生成有单独额度。
- 上传图和生成图进入统一图片流水线。
- OpenAI Moderation 已接入本地配置，用于辅助成人内容判断。

限制：

- `image_create_generated_placeholder()` 在真实图片生成失败时会回退到本地占位 SVG/WebP。这样体验不中断，但可能掩盖供应商失败。建议未来在 UI 中给出“图片生成服务失败，已使用占位图”的轻提示。
- 图片生成 prompt 有长度钳制，能控成本，但复杂创意请求可能被压缩。

## 6. UI/UX 审计

### 6.1 已达成

- 当前主界面保持 TUI 风格，视觉方向统一。
- 顶部状态栏、消息区、底部输入框的 app shell 结构清晰。
- 最大宽度约束为 750px，桌面不再过宽。
- 移动端无整体页面滚动，输入框保持在视口内的方向正确。
- 滚动条改为靠近边缘、自动显隐，符合当前视觉目标。
- 用户消息靠右，AI 消息靠左，阅读路径清楚。
- 上传卡片已改为提交式，不再选图即结束说明。
- 上传后会给 AI 注入图片事件，让 AI 继续自然回复。
- 邮箱绑定以卡片为主，用户只发独立邮箱时也能智能绑定。
- 生成中使用占位动画，生成完成后 iframe 替换，避免半成品页面闪烁。
- 交付卡片提供链接、二维码、打开页面和页面图片导出。
- 三语固定 UI 已实现，AI 回复语言按语意自适应的方向合理。

### 6.2 需要继续观察

- iOS Safari 输入框白屏/飞走问题无法用本地 Chromium 完全证明已修复。现有 CSS/JS 已有 iOS 规避措施，但仍需要真机 Safari 回归。
- TUI 风格下隐藏原生滚动条会降低部分用户对“可滚动”的发现度。当前已加入滚动状态提示，问题可接受。
- 交付卡片从“全宽沉重”改轻后方向正确，但最终视觉应继续以 Figma 设计为准。
- `Page Forge Stream` 等少量视觉文字是否三语化，需要产品决策：如果它是品牌化组件名，可以保持英文；如果是界面提示，应进入 i18n。
- 页面截图导出现在是 PNG，但部分按钮或文件名可能仍显示 `webp` 语义，建议统一为“下载页面图片”或按扩展名动态命名。

## 7. 主要发现与建议

### P1：上线前必须验证

1. 真实聊天模型与真实生成模型未在本轮本地验证。  
   本地诊断显示 chat/gen key 缺失。上线前必须执行 live AI 诊断，确认流式格式、错误处理、模型响应中的动作标记稳定。

2. SMTP 未在本地配置。  
   登录验证码、修改链接邮件只验证了 fallback 设计，未验证真实发信成功率和垃圾箱表现。

3. Turnstile 本地关闭。  
   生产发布前必须打开，并验证失败时不扣额度、不进入生成。

4. iOS Safari 仍需真机验证。  
   这是目前 UI 风险里最值得复测的一项。

### P2：建议近期修

1. 页面截图下载文件名与实际 PNG 格式统一。  
   如果截图产物为 `page-shot.png`，前端下载名不应继续叫 `xlog-page.webp`。

2. 图片生成失败 fallback 应给用户一个轻提示。  
   避免用户误以为已经拿到真实 AI 图片。

3. 为 `quota_counters` 增加历史清理。  
   可以保留 60 或 90 天，减少长期 SQLite 膨胀。

4. 考虑将域名前缀偏好从“系统事件消息”迁移到结构化字段。  
   不是当前阻断，但有助于后续更干净地组织生成上下文。

5. 对生成 HTML 校验逐步升级到 DOM 解析。  
   当前正则校验够用，DOM 校验更适合长期防御。

### P3：可择机优化

1. 清理旧 V1 文件和未使用的辅助函数。  
   当前 redirect stub 可以保留，但历史 helper 代码可继续瘦身。

2. 统一品牌/组件名称的三语策略。  
   决定哪些是品牌名，哪些是界面提示。

3. 补充更细的可访问性语义。  
   TUI 视觉不影响可用性，但卡片按钮、状态提示可进一步加 aria。
